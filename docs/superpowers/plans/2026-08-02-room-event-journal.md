# Room Event Journal and Idempotency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make multiplayer commands durably idempotent and let reconnecting room clients receive ordered missing events before falling back to a snapshot.

**Architecture:** PostgreSQL records one wire-compatible room envelope for every accepted command in the same transaction that advances `rooms.sequence`. A command receipt is keyed by room, actor and client UUID; duplicate commands return the already-recorded envelope without executing game rules again. The realtime hub asks the room service for events newer than `since`; it sends contiguous retained events or a current snapshot when a gap exists. Redis remains a post-commit fan-out mechanism only.

**Tech Stack:** Go 1.24, pgx/v5, PostgreSQL 16 JSONB, Redis Pub/Sub, Svelte 5, Vitest.

## Global Constraints

- PostgreSQL is the only authority for room state, sequences, event journal and command receipts.
- Every game rule remains in the generic `game` engine; no demo-specific runtime branches are added.
- Replayed events are envelopes produced after a committed transaction; Redis is never used as durable storage.
- Command IDs are UUID strings generated by the browser and must not contain a result selected by the client.
- A reconnecter who is no longer a member must receive no journal event or snapshot.
- Missing or pruned journal sequences cause a full authenticated snapshot, never an invented transition.

## Self-review

- The plan writes the command receipt and event row in the same PostgreSQL transaction as the room sequence change.
- A duplicate roll never invokes the RNG and a duplicate chat never creates a second persistent message.
- Replay returns only contiguous retained envelopes; a missing sequence always falls back to an authenticated snapshot.
- Redis receives post-commit events only and remains non-durable fan-out.
- Invite links, presence and rate limits are intentionally outside this isolated journal plan and remain explicit release work.
