# Rollboard

**Самостоятельно размещаемая платформа для создания и игры в пошаговые настольные игры в браузере.**

Rollboard — это универсальный движок, а не клон «Монополии». Игра здесь —
*данные*: граф поля плюс список действий, поэтому новая игра означает новое
описание, а не код на бэкенде. Соберите поле в визуальном редакторе,
опубликуйте неизменяемую версию, откройте комнату и играйте с людьми в
реальном времени.

Go на бэкенде · Svelte 5 на фронтенде · PostgreSQL · Redis · Docker

## Что это умеет

- **Визуальный редактор поля** — клетки, направленные рёбра, свойства и действия.
- **Правила как данные** — поведение задаётся списками `ActionDefinition`, а не кодом.
- **Движение по ориентированному графу** — поле является графом, поэтому развилки и односторонние пути работают.
- **Аккаунты и гости** — авторы регистрируются, игроки могут войти в комнату без аккаунта.
- **Приватные черновики и неизменяемые опубликованные версии** — комната закреплена за версией, поэтому игра не меняется под игроками.
- **Сетевые комнаты в реальном времени** — кубик и движение считает сервер, есть чат и модерация со стороны хозяина комнаты.
- **Игра на одном устройстве** — с явными экранами передачи хода.
- **Два языка, остальные — без пересборки** — см. [Переводы](#переводы).
- **Светлая и тёмная темы**, доступность с клавиатуры, работает вплоть до ширины телефона.

Сервер всегда авторитетен. Браузер отправляет намерения («хочу бросить кубик»),
а не результаты.

## Быстрый старт

Нужен **Docker** с плагином Compose. Больше ничего.

```bash
git clone https://github.com/mirivlad/rollboard.git
cd rollboard
docker compose up --build
```

Откройте <http://localhost:8080>, создайте аккаунт и выберите шаблон.

Одна команда собирает образ и поднимает PostgreSQL, Redis и приложение.
Миграции применяются при запуске сами.

### Запуск из исходников

Для разработки понадобятся ещё **Go 1.24+** и **Node.js 20+**:

```bash
cd frontend && npm install && cd ..
./scripts/dev.sh
```

Поднимутся PostgreSQL и Redis в Docker, бэкенд на `:8080` и Vite на
<http://localhost:5173>.

## Развёртывание всерьёз

`docker compose up` годится, чтобы попробовать, но это не публичное
развёртывание. Для него:

### 1. Возьмите готовый стек

[`deploy/portainer-stack.yaml`](deploy/portainer-stack.yaml) забирает
опубликованный образ вместо сборки и отказывается стартовать без пароля к базе
и адреса приложения.

```bash
export POSTGRES_PASSWORD='длинная случайная строка'
export ROLLBOARD_APP_ORIGIN='https://rollboard.example.com'
docker compose -f deploy/portainer-stack.yaml up -d
```

Тот же файл работает как стек Portainer: вставьте его и задайте те же
переменные.

### 2. Поставьте за TLS

Rollboard не терминирует TLS. Поставьте его за обратным прокси и отдайте
сертификаты ему. Приложению нужно лишь, чтобы `ROLLBOARD_APP_ORIGIN` совпадал с
публичным адресом: от этого значения зависят и CORS, и проверка источника
WebSocket.

Пример с Caddy:

```caddyfile
rollboard.example.com {
    reverse_proxy localhost:8080
}
```

**Ставьте `ROLLBOARD_COOKIE_SECURE=true`, когда сайт отдаётся по HTTPS.** Иначе
куки сессии уйдут и по обычному HTTP.

**Задайте `ROLLBOARD_TRUSTED_PROXIES` — адрес вашего прокси.** Все запросы
приходят от прокси, поэтому без этого ограничение попыток входа считает всех
посетителей одним человеком, и несколько неудачных попыток любого из них
блокируют вход остальным. Заголовок читается **только** от перечисленных здесь
адресов: от прямого клиента он ничего не стоит, его может написать кто угодно.

```bash
# Caddy или nginx на том же хосте
ROLLBOARD_TRUSTED_PROXIES=127.0.0.1,::1
# nginx в соседнем контейнере в сети Docker по умолчанию
ROLLBOARD_TRUSTED_PROXIES=172.16.0.0/12
```

В nginx передайте адрес дальше:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Host $host;
    # Живые комнаты — это WebSocket.
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

### 3. Делайте резервные копии PostgreSQL

Всё долговременное лежит в PostgreSQL: аккаунты, черновики, опубликованные
версии, комнаты и журнал событий. Redis переносит только рассылку между
процессами, его потеря не теряет данных.

```bash
docker compose exec -T postgres pg_dump -U rollboard rollboard | gzip > rollboard-backup.sql.gz
```

Восстановление:

```bash
gunzip -c rollboard-backup.sql.gz | docker compose exec -T postgres psql -U rollboard rollboard
```

### 4. Обновление

```bash
docker compose pull
docker compose up -d
```

Миграции применяются при запуске в транзакции под advisory-блокировкой, поэтому
одновременный старт нескольких реплик безопасен. **Всё равно сначала сделайте
копию** — миграции необратимы.

## Настройка

Вся настройка — переменные окружения. За основу возьмите
[`.env.example`](.env.example).

| Переменная | По умолчанию | Что делает |
|------------|--------------|------------|
| `ROLLBOARD_ADDR` | `127.0.0.1:8080` | Адрес прослушивания. В образе — `0.0.0.0:8080`. |
| `ROLLBOARD_DATABASE_URL` | `postgres://rollboard:rollboard@127.0.0.1:5432/rollboard?sslmode=disable` | Строка подключения к PostgreSQL. |
| `ROLLBOARD_DATABASE_MAX_CONNS` | `20` | Максимум соединений в пуле **на реплику**. |
| `ROLLBOARD_REDIS_URL` | `redis://127.0.0.1:6379/0` | Redis, только для рассылки между репликами. |
| `ROLLBOARD_APP_ORIGIN` | `http://127.0.0.1:5173` | Публичный адрес. Задаёт CORS и проверку источника WebSocket. **Должен совпадать с реальным.** |
| `ROLLBOARD_COOKIE_SECURE` | `false` | `true` за HTTPS. |
| `ROLLBOARD_SESSION_TTL` | `720h` | Время жизни сессии, в формате длительности Go. |
| `ROLLBOARD_AUTH_RATE_LIMIT` | `10` | Попыток входа в минуту, на адрес, на реплику. |
| `ROLLBOARD_TRUSTED_PROXIES` | не задано | Адреса или подсети, чьему `X-Forwarded-For` можно верить. **Задайте за обратным прокси**, иначе все посетители делят один лимит. |
| `ROLLBOARD_LOCALES_DIR` | не задано (`/app/locales` в образе) | Каталоги переводов. |
| `ROLLBOARD_UPLOADS_DIR` | не задано (`/app/uploads` в образе) | Где хранятся загруженные авторами картинки. Пусто — загрузка выключена. |
| `ROLLBOARD_UPLOAD_QUOTA_MB` | `50` | Сколько всего может занимать один аккаунт. |
| `ROLLBOARD_UPLOAD_TOTAL_MB` | `5000` | Сколько хранит всё развёртывание. |
| `ROLLBOARD_UPLOAD_RATE_LIMIT` | `30` | Загрузок в минуту на аккаунт. |
| `ROLLBOARD_STATIC_DIR` | не задано (`/app/frontend` в образе) | Собранный фронтенд. В разработке не нужен — его отдаёт Vite. |

Неверные значения роняют запуск с внятным сообщением, а не при первом
обращении.

## Переводы

Интерфейс поставляется на **английском** и **русском**. Каталоги — обычные
JSON-файлы, читаемые с диска на каждом запросе, поэтому новый язык **не требует
ни пересборки образа, ни изменений в коде**:

```bash
cp locales/en.json locales/de.json
```

Переведите значения и перезапустите приложение. Язык сам появится в
переключателе. Непереведённые ключи берутся из английского, поэтому частичный
перевод полезен сразу.

Подробности, включая формы множественного числа и перевод серверных ошибок, —
в **[docs/ru/I18N.md](docs/ru/I18N.md)**.

## Как описывается игра

Игра — это поле (клетки и направленные рёбра) плюс правила (кубики, ресурсы,
типы клеток). У каждой клетки могут быть списки действий `onLand` и `onPass`,
которые движок выполняет единообразно.

```json
{
  "type": "if_cell_unowned",
  "then": [{
    "type": "offer_choice",
    "title": "Купить эту улицу за 100?",
    "options": [
      { "id": "buy", "title": "Купить (100)", "then": [
        { "type": "lose_resource", "resource": "money", "amount": 100 },
        { "type": "set_cell_owner", "target": "current" }
      ]},
      { "id": "skip", "title": "Пройти мимо", "then": [] }
    ]
  }],
  "else": [{
    "type": "if_cell_owned_by_other",
    "then": [{ "type": "transfer_resource", "resource": "money", "amount": 20, "target": "owner" }]
  }]
}
```

Этот фрагмент — вся «покупка недвижимости и аренда». В движке нет ни строчки
про недвижимость.

**Типы действий:** `gain_resource`, `lose_resource`, `transfer_resource`,
`set_cell_owner`, `set_cell_level`, `set_cell_mortgaged`, `offer_choice`,
`random_branch`, `start_auction`, `if_cell_unowned`, `if_cell_owned_by_current`,
`if_cell_owned_by_other`, `if_cell_level_ge`, `if_cell_mortgaged`,
`if_cells_ge`, `for_each_cell`, `if_resource_ge`, `if_stat_ge`, `if_has_item`,
`grant_item`, `remove_item`, `equip_item`, `unequip_slot`, `use_item`,
`reveal_cells`, `move_player_to`, `skip_turns`, `finish_game`,
`eliminate_player`, `log_message`.

Каждое из них редактируется визуально: список действий генерируется из схемы, а
тест валит сборку, если движок получил действие, до которого редактор не
дотягивается. Величины можно **вычислять**, а не задавать («урон этой клетки
минус моя защита, но не меньше нуля») — именно поэтому броню имеет смысл
надевать.

Действия умеют спрашивать и о **других клетках** — «сколько вокзалов у
владельца этого?», «принадлежит ли вся цветовая группа одному игроку?» — и
выставлять клетку на **аукцион**, где ставки идут по кругу. И то и другое
собирается из выпадающих списков и разобрано с примерами в
**[docs/ru/AUTHORING.md](docs/ru/AUTHORING.md)**.

Кроме поля и ресурсов описание может объявлять **предметы** со слотами
экипировки и бонусами, **уровни** с порогами опыта и очками прокачки,
**закрытые клетки**, которые остаются рубашкой вверх до исследования, и
**свободное движение**, где бросок — это бюджет, который тратится на любую
клетку в пределах досягаемости.

Два встроенных шаблона показывают размах:

- **Монополия** — 40 клеток чистых данных: покупка, аренда, растущая от
  застройки, цветовые группы с удвоением аренды при полном владении, аренда
  вокзалов, умножающаяся на число владений, аукционы за то, что никто не купил,
  залог, тюрьма, карточки шанса и банкротство.
- **Подземелье** — карта 6×6, которую исследуют клетка за клеткой: параметры,
  уровни, добыча, которую надевают, ловушки, враги, чья сложность проверяется
  против эффективной атаки, и дракон.

Ни в одном из них нет ни строчки специального кода в движке.

**Условия рёбер:** `always`, `dice_total_even`, `dice_total_odd`,
`dice_total_in`, `manual_choice`, `pay_resource`, `player_resource_at_least`.

Модель движка, ход сессии и правила ветвления описаны в
**[docs/ru/ARCHITECTURE.md](docs/ru/ARCHITECTURE.md)**.

## Разработка

| Команда | Что делает |
|---------|------------|
| `make dev` | PostgreSQL, Redis, бэкенд и фронтенд вместе |
| `make test` | Полный набор Go **с интеграционными тестами против настоящих PostgreSQL и Redis** |
| `make test-unit` | Только модульные тесты, Docker не нужен |
| `make check` | gofmt, vet, тесты Go, svelte-check, vitest, сборка фронтенда, проверка шаблонов |
| `make smoke` | Сквозная проверка API |
| `make fmt` | gofmt для бэкенда |
| `make build` | Боевые сборки |
| `./scripts/ui-shots.sh` | Прогнать настоящий браузер и пересоздать скриншоты |

`make test` требует Docker и отказывается работать с чем-либо, кроме базы
`rollboard_test`, потому что интеграционные тесты чистят таблицы.

CI выполняет те же проверки на каждый push и падает, если хоть один тест был
*пропущен*: набор, молча пропускающий интеграционные тесты, рапортует об успехе,
ничего не доказав.

Соглашения проекта — в [AGENTS.md](AGENTS.md), как участвовать — в
[CONTRIBUTING.md](CONTRIBUTING.md).

## Текущие ограничения

Сказано прямо, чтобы вы могли решить до развёртывания:

- **Нет публичного каталога игр.** Комнаты передаются по ID или ссылке-приглашению.
- **Нет индикатора присутствия.** Видно, кто участник, но не кто сейчас подключён.
- **Ограничение частоты — на реплику.** За N репликами эффективный потолок равен N лимитам. За прокси нужен ещё `ROLLBOARD_TRUSTED_PROXIES`, иначе все посетители делят один лимит.
- **Нет ботов.** Каждый игрок — человек.
- **Нет отмены хода.** Журнал фиксирует произошедшее, но не откатывает его.
- **Ставки на аукционе шаговые.** Сервер предлагает несколько повышений, произвольную сумму ввести нельзя.
- **Нет табличных подстановок.** Ступенчатые значения пишутся цепочкой `if_*_ge` — работает, но длинно.
- **Журнал не подрезается.** Политика хранения не реализована; нагруженным развёртываниям она понадобится.
- **Нагрузочное тестирование не проводилось.** Любые оценки ёмкости считайте недоказанными.
- **Загружать можно только картинки**, не больше 2 МБ, тип определяется по байтам, а не по имени файла. SVG отклоняется, потому что может нести скрипт. Квоты ограничивают объём; картинки, которые больше нигде не используются, автоматически не удаляются — их удаляет автор.
- **Нет OAuth** и никакого авторского кода.
- **Мини-игры зарезервированы, но не запускаются.** `launch_minigame` — типизированная версионированная заглушка, которую публикация намеренно отклоняет, чтобы чужой код не исполнялся в процессе приложения.

Текущее состояние, включая то, что именно и как проверено, — в
[docs/ru/CURRENT_STATE.md](docs/ru/CURRENT_STATE.md).

## Если что-то не работает

**Порт занят.** Смените `ROLLBOARD_ADDR` или освободите порт:

```bash
lsof -ti :8080 | xargs kill -9
```

**WebSocket не подключается или запросы блокирует CORS.**
`ROLLBOARD_APP_ORIGIN` не совпадает с адресом, по которому вы работаете. Он
задаёт обе проверки.

**Вход вроде проходит, но сразу выбрасывает.** `ROLLBOARD_COOKIE_SECURE=true`
при работе по обычному HTTP — браузер выбрасывает куку.

**База отказывает в подключении.** Проверьте состояние сервиса:

```bash
docker compose ps postgres
docker compose logs postgres
```
